What this is

Type a portfolio — ticker/weight pairs — and it grows as a small forest: one tree-ring glyph per holding, sized by how much of the portfolio it is, plus one larger composite tree representing the whole portfolio's combined year-by-year performance. Every holding glyph is the exact same real, computed tree from the Tree Rings forest — same rings, same scars, same encoding. The composite is synthesized from those real per-holding numbers (see below for exactly how).

How to read it

Holding glyphs: identical encoding to the main forest. Ring width = that year's growth (log return, monotone-squashed). Ring color = that year's return (red→tan→green), darkness = that year's realized vol — both normalized within the asset's own class. Scars are real drawdown episodes on that asset's whole history. Glyph size is scaled by portfolio weight: radius ∝ √(weight), so glyph area — not radius — is proportional to how much of the portfolio it is (a 40% holding's disk covers ~4× the area of a 10% holding's, not 4× the width). Tiny weights are floored to a minimum readable size.

The composite tree (top, larger, amber bark) has one ring per calendar year in which at least one holding was alive. Each ring's return is Σ wi·(1+ri) − 1, where ri is that holding's real total return for that year and wi is its portfolio weight renormalized over only the holdings alive that year (a ticker that didn't exist yet, e.g. BTC before 2016, simply isn't in the sum, and everyone else's weight scales up to fill the gap). Ring width/color follow from that composite return exactly as for a real asset. Ring darkness (vol) is the weight-averaged vol of the alive members that year — an approximation, not the true volatility of the combined return stream (see caveats). A scar appears on any composite year where the composite return fell below −15% — a simplified single-year gate (see caveats).

The analogy

If the main forest is a stand of individually-grown trees, a portfolio is an orchard you planted on purpose — you chose the mix and the proportions. The composite tree is like grafting a single trunk from cuttings of every tree in the orchard: each year's growth ring on the graft is a blend of what its parent trees did that year, weighted by how much of the graft came from each. It's not a tree that really grew that way — it's an honest accounting of what the blend would have done.

Caveats — read before trusting the composite

Annual rebalancing assumption. The composite return formula implicitly assumes the portfolio is rebalanced back to target weights at the start of each calendar year. A real buy-and-hold portfolio drifts between rebalances (winners grow to a larger share, losers shrink) — this composite does not model drift.

Vol is an approximation. Composite ring darkness is the weight-averaged vol of the members, not the actual volatility of the combined portfolio return series. Real portfolio volatility depends on how the holdings move together (correlation); this approximation ignores diversification benefits entirely, so it likely overstates how volatile a diversified portfolio really was.

Scar gate is simplified. Per-holding scars track a real peak→trough→recovery drawdown episode across years (that machinery needs daily prices, which this frontend-only page doesn't have for the composite). The composite instead just flags any calendar year where the composite's own year return was worse than −15%, with no tracking of whether/when it "recovered." Treat composite scars as "a rough year," not a modeled drawdown.

Weight renormalization in years where a holding wasn't alive yet can inflate the effective influence of whatever else was alive that year — e.g. a 3-way portfolio where one leg IPO'd in 2023 is really a 2-way portfolio (renormalized) for every year before that.
